## Project Summary

Husky-Review (product name: "Actionable UWB Resume Review") is a React/Vite/TypeScript web app aimed at UWB students who want resume feedback tied to **real, verified UWB activities** (clubs, courses, fellowships, events, research roles) rather than generic AI suggestions. The current repository contains a polished, mocked frontend plus authenticated upload plumbing (Auth0 + Supabase + Vercel functions), with the AI pipeline still described as planned work. Contributors visible in git history: Ghosty / DevGhosty (Steven Rosas, ~35 commits) and Jacob Arquiza (2 commits).

## Suggested Improvements & New Features

### Code Quality & Technical

- Add a live deployment URL (and "Sign in with @uw.edu" caveat) to the **top** of `README.md`. Graders will not dig through `DEPLOYMENT_CHECKLIST.md` to find it.
- Replace `src/data/mockData.ts` recommendations with rows fetched from a real Supabase `uwb_activities` table; the schema in `supabase/schema.sql` should grow a table like `activities (id, type, title, url, description, active, last_verified_at, embedding vector(1536))`.
- The "Analyze" path in `src/pages/dashboard-page.tsx` line 78 currently uploads then calls `runMockAnalysis()` (review-context.tsx line 106). Wire it to a new `api/analyze.ts` Vercel function that actually parses the resume PDF (e.g., `pdf-parse`) and calls Claude.
- Add at least a smoke test or Playwright run for the marketing page and the upload happy path; CI is only `tsc --noEmit` plus `verify-auth-boundary.mjs`.
- The 566-line `src/components/hero-section.tsx` and 502-line `src/pages/profile-page.tsx` are getting unwieldy — split into smaller components.
- Consider removing or moving the heavy `mockups/husky-review-preferred-career-command-center.png` (PNG checked into source) if it's not used at runtime.
- `src/data/uwb-catalog.ts` is only 63 lines of interest categories. Either rename it to `activity-categories.ts` or actually populate it with the 50+ verified entries from the proposal.

### UI / UX Improvements

- Add a "Demo without sign-in" path. Right now `MarketingPage` exists but the actual workspace (`/app/*`) requires Auth0 + @uw.edu. A grader without a UW Google account cannot evaluate any functionality. A read-only sample roadmap on a public route would solve this.
- Surface a clear "this is a mock / not yet live AI" banner on the dashboard while the pipeline is incomplete — the README is honest, but the in-app UI implies it's working.
- Move the "Use sample resume" affordance (`upload-panel.tsx` line 132) out of the upload card and into the empty state of the dashboard so it does not look like a debug shortcut.
- Add a verification-date badge to each recommendation card (`src/components/recommendation-card.tsx`) so the verified-database claim is visible to the user, not just in the proposal.

### New Features

- **Real verified UWB catalog**: schedule a weekly verification cron that re-checks each activity's source URL (HTTP 200 + last-modified) and flips `active=false` if the page disappears.
- **Deadline-aware roadmap**: take the application deadline already collected in the upload panel and compute true "in-time" vs "next-time" cutoffs by date, not just labels.
- **Faculty/lab pairing for research roles**: scrape the UWB CSS faculty directory once, store interests, and let students filter "research roles" by faculty research area.
- **Resume version diff**: when a student re-uploads, show what changed and which recommendations are now satisfied. This makes the verified-DB feedback loop tangible.
- **Anonymous outcome log**: opt-in record of "did you actually do this activity → did you get the role?" so the team can later report real outcome data, which would strengthen the UW Community Impact story.

### AI Integration Enhancements

This is where the project most needs movement before May 31. Suggested minimum-viable AI integration that fits the proposal:

1. Add `@anthropic-ai/sdk` to `package.json` and create `api/analyze.ts`.
2. Server-side: take the uploaded resume (already in Supabase storage per `api/resumes/upload.ts`), extract text with `pdf-parse`, and call Claude once to produce a structured `{ skills_present[], skills_missing[], keyword_gaps[] }` JSON object (use Claude's tool-use / JSON output).
3. Pre-compute embeddings for each row in a real `uwb_activities` Supabase table (one offline script). Store as `vector(1536)` using the `pgvector` extension.
4. At request time, embed the `skills_missing` + job description, run a cosine similarity search via Supabase RPC, take top-K activities.
5. Final Claude call ranks the top-K and tags each as `in_time` vs `next_time` based on the activity's typical lead time vs the user's deadline.
6. Stream the result back to `dashboard-page.tsx` and replace `runMockAnalysis()`.

Even a partial version of steps 1-2 would move the AI Integration score from ~3 to ~8-10. Document API spend caps (this was the one weakness Claude flagged on the proposal itself — see `docs/proposal.md` lines 169-174).

Add an `ai/` or `lib/ai/` directory with prompts checked into the repo so the AI logic is reviewable and reproducible — this is the kind of structural evidence the "AI is central" rubric criterion is looking for.
